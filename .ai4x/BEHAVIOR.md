# Application development behavior

Explicit user instructions and host constraints take precedence. Inspect the
actual checkout, branch, worktree and relevant changes before working. Preserve
unrelated, unknown and private material. Existing files do not grant authority to
migrate, delete, publish or operate on another repository or portfolio.

Keep this application reusable. Do not add personal portfolio data, personal
defaults, machine paths or links to a private instance's workflow. Accept an
instance only through an explicit path. Keep one owner for each fact; source
filing, presentation, activity tracking and goal evidence have distinct owners.

Write code and engineering records in US English. Preserve authored content in
its original language. User-facing guidance targets English and German; the
retained interface currently contains German labels. Do not describe planned
localization or architecture as delivered behavior.

Use small cohesive changes and proportionate verification. Run the relevant
checks; report what changed, evidence and remaining limitations. Application
operations are shared by entry points. Keep source interpretation and business
rules out of duplicate UI or agent implementations.

AI assistance does not establish an accepted ai4X curation, activate an agent or
grant execution authority. Separate proposals, implementation, verification,
human acceptance and publication. Do not invent issue numbers, release history,
remote locations or approval records. Consult [TEAM.md](TEAM.md) when specialist
input or independent review is needed.

Maintain concise durable context when a decision changes. STATE is a return
pointer, not a source of live work status or authorization. For a status request,
report observed state and the next proposed action. Continue work only within
the user's actual authorized scope.

Use the same branch name locally and on the remote; name new worktree directories
after that branch to keep the workspace unambiguous. Preserve existing PR/review
history when reconciling older naming differences.
