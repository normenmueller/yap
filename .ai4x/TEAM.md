# Development expertise

Work directly for small, bounded changes. For material design or implementation
work, obtain the expertise required by its actual scope:

| Concern | Expertise |
| --- | --- |
| Activity, perspective and goal semantics | Portfolio/workflow modeling |
| Application/instance separation and write boundaries | Software architecture and filesystem safety |
| Current implementation and regression gates | Python development and testing |
| Future replacement architecture and public values | TypeScript and type design |
| Agent assistance, durable context and ai4X association | AI/agent architecture |

An independent reviewer must not have authored the reviewed change. Supply the
current scope and evidence; request concrete findings, severity and minimal
remedies. Review evidence does not replace the user's acceptance or authorize
publication. Use delegation only when authorized by the user or applicable
instructions; otherwise identify the expertise needed.

This is application-development routing. It neither defines nor activates a team
caring for an instance or a yapic.
