# Python application development team

The owner selected Python as yap's application core until further notice and
explicitly authorized Gertrud to coordinate core-team and independent specialist
work. Small bounded changes can be handled directly. Material Python design,
implementation and quality work must obtain the relevant capabilities below and
an independent review. Read [python-quality.md](python-quality.md) for the working
method and evidence required; listing expertise alone does not deliver quality.

| Capability | Cognitive work and responsibility |
| --- | --- |
| Python software architecture and design | Decompose by semantic responsibility; inspect dependency direction, cohesion and application/instance boundaries; compare the smallest coherent alternatives. |
| Type theory and Python type design | Model valid states and identities; distinguish structural/static claims from runtime guarantees; design checked construction, narrow protocols and ownership of mutable values. |
| Portfolio/workflow semantics | Preserve activity/version identity, explicit relationships, arrangements, measurements and evidence; challenge unsupported inference, including quip qualification. |
| Python correctness and filesystem safety | Trace malformed inputs, stale plans, symlinks, partial writes and failures; preserve unknown content and bound local/provider effects. |
| Python runtime and performance | Find actual repeated work and complexity costs; measure representative cold/warm paths before optimization and verify semantic equivalence. |
| Verification and adversarial review | Derive counterexamples from contracts; review type/runtime tests, deterministic results, preservation and recovery independently of the author. |
| AI/agent and integration architecture | Separate durable definitions, real care references and assignment authority; design bounded Git/provider operations and uncertain-outcome handling. |
| Product workflow and presentation | Explain decisions in concise PO language; retain CLI/editor/AI-host paths, accessibility, localization and publication behavior. |

Gertrud owns synthesis, scope and a clear recommendation to the owner. A task may
combine capabilities when the reviewer can demonstrate the required expertise;
do not create one agent per row by default. Add a targeted external specialist
when the scope exceeds the core team's coverage. Browser work can call for
TypeScript expertise; this does not reopen the accepted core-language decision.

Independent reviewers must not author the reviewed change. Supply its scope,
revision and actual evidence; request concrete findings, severity, minimal remedies
and verification gaps. Resolve findings and obtain a recheck. A reviewer may find
the scope insufficient; never prescribe the score or mistake a passing check for
whole-codebase acceptance. Review does not replace the owner's acceptance.

These are application-development capabilities and authorized review practices,
not an assertion of provider-accepted ai4X curation or activation of instance care.
